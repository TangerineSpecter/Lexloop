# 动态复习算法

## 目标

Lexloop 不把复习固定为一组死板日期，而是以艾宾浩斯的“先密后疏”为基础，根据每个单词的答题表现与实际复习行为动态安排下一次复习。

- 新词和到期复习词会合并进入当天学习计划。
- 用户完成一个学习分组后，系统保存每个单词本次答题是否正确，并重新计算复习时间。
- 用户必须手动点击“标记掌握”才会移入已掌握；算法只决定复习节奏与巩固提示。

## 单词状态与流转

```text
新单词 ──创建学习计划──> 学习中 (LEARNING)
新单词 ──加入复习──────> 复习中 (REVIEWING，今天到期)
学习中/复习中 ──完成分组──> 复习中 (写入下一次复习时间)
复习中 ──标记掌握──────> 已掌握 (MASTERED，全词书排除)
已掌握 ──移除掌握──────> 可再次作为新词出现
```

“待复习单词”只展示两类词：

1. 当天从新单词手动加入复习的词；
2. `nextReviewAt` 小于或等于当前时间的复习中词。

“学习中”列表汇总所有学习中词书里的 `LEARNING` 与 `REVIEWING` 单词，不受当前默认词书限制。

## 输入数据

每个用户、每本词书中的单词维护以下数据：

| 字段 | 含义 |
| --- | --- |
| `totalAttempts` / `correctAttempts` | 累计作答次数与正确次数；两者计算累计正确率。 |
| `reviewCount` | 完成学习或复习分组的次数。 |
| `consecutiveCorrect` | 连续答对次数；当前用于保留趋势数据，后续可作为强化因子。 |
| `lastIntervalDays` | 上次系统安排的复习间隔（天）。 |
| `lastReviewedAt` | 最近一次提交分组结果的时间。 |
| `nextReviewAt` | 下一次进入待复习列表的时间。 |
| `postponedCount` | 用户“稍后再学”的累计次数。 |
| `familiarity` | 由动态陌生程度反推的稳定度（`100 - 陌生程度`）。 |

每次答题还会写入一条 `WordReviewAttempt`，用于审计、统计和以后扩展按题型分析。

## 调度规则

### 1. 基础间隔

首次完成单词学习时，基础间隔为 1 天。之后使用上次安排的间隔作为下一轮的基础：

```text
baseInterval = max(lastIntervalDays, 1)
```

这使高质量复习自然呈现约 1 天、2 天、4 天、9 天、20 天的“先密后疏”节奏，而非固定日历表。

### 2. 累计正确率与质量系数

完成分组后先计算包含本次结果的累计正确率：

```text
accuracy = (correctAttempts + 本次是否正确) / (totalAttempts + 1)
```

本次正确时按累计正确率选用质量系数：

| 累计正确率 | 系数 | 含义 |
| --- | ---: | --- |
| ≥ 85% | 2.20 | 掌握较稳，可明显拉长间隔。 |
| 65%–84% | 1.45 | 正常巩固，温和拉长间隔。 |
| < 65% | 0.90 | 虽然答对，但总体不稳，不扩大节奏。 |

本次答错时系数固定为 `0.45`，让单词尽快回到复习中。

### 3. 逾期修正

如果用户晚于安排日期完成复习，系统认为遗忘风险上升，并缩短下一次间隔：

```text
overdueDays = max(当前时间 - nextReviewAt, 0)
overdueFactor = max(0.45, 1 - min(0.50, overdueDays / baseInterval × 0.18))
```

逾期不会直接判定本次回答错误；它只是降低间隔上限，避免“很久没复习但碰巧答对”导致安排过远。

延期次数还会形成独立修正：

```text
postponeFactor = max(0.55, 1 - min(0.40, postponedCount × 0.08))
```

### 4. 最终间隔

```text
intervalDays = clamp(
  round(baseInterval × qualityFactor × overdueFactor × postponeFactor),
  1,
  180
)
nextReviewAt = 完成时间 + intervalDays
```

正常情况下间隔最短为 1 天、最长为 180 天。若一个词已经至少完成 4 次复习，但累计正确率仍低于 60%，最长间隔进一步限制为 2 天，避免长期反复遗忘。

## 巩固提示

学习中列表不把低正确率直接等同于“不会”。它根据历史给出学习建议：

| 条件 | 提示 | 含义 |
| --- | --- | --- |
| 尚未答题，或正确率 ≥ 70% | 稳定学习 | 继续按当前节奏学习。 |
| 已答题且正确率 < 70%，复习次数 < 4 | 需巩固 | 处于早期学习阶段，建议多接触例句和词义。 |
| 复习次数 ≥ 4 且正确率 < 60% | 重点巩固 | 持续不稳定，建议改变记忆线索、语境或练习方式。 |

提示不自动将单词移入已掌握，也不阻止用户手动标记掌握。

## 陌生程度

陌生程度不是单纯用错误率代替，而是在每次完成练习时综合计算 0–100 分：

```text
陌生程度 =
  正确率风险（最高 58）
  + 逾期风险（最高 18）
  + 实际间隔超过计划间隔的风险（最高 8）
  + 延期风险（最高 10）
  + 多次复习仍低正确率的持续困难风险（14）
  - 连续答对带来的稳定修正（最高 12）
```

- 初学次数少且正确率低，只表示“需要巩固”，不会过早判断为持续困难。
- 至少复习 4 次且正确率仍低于 60% 时，额外增加持续困难风险，并把下一次间隔限制在 2 天内。
- 逾期和延期只增加遗忘风险，不会伪造成一道错题。
- 连续答对会降低陌生程度，但不会自动标记掌握。

数据库中的 `familiarity` 保存 `100 - 陌生程度`。学习统计按陌生程度排序，用于提示优先复习对象；它不是考试成绩。

## “稍后再学”

待复习词点击“稍后再学”后：

1. `nextReviewAt` 设为明天零点；
2. `postponedCount` 加 1；
3. 不修改 `lastReviewedAt` 与累计正确率。

因此下一次真正完成复习时，距上次复习的实际时间会更长；逾期修正会在调度中反映这部分遗忘风险。延期不是答错，也不会直接降低正确率。

## 计划与结果写入

学习计划由 API 创建并持久化，包含今天到期复习词以及当前展示的新词。分组模式会先随机打乱，再以 2–5 个词动态分组；独立单词模式每个词单独形成一篇材料。前端完成分组后只提交每个词的所选答案与作答耗时；答案必须与当前分组逐词匹配。服务端根据计划中保存的题目和正确答案判分，并在一个事务中：

1. 写入答题记录；
2. 更新该词的累计数据与下次复习时间；
3. 标记计划分组完成；
4. 全部完成后将计划标记为完成。

这样刷新页面或切换设备后，当前学习序列、正确率和复习时间仍保持一致。

## 后续可调参数

当前阈值集中在 `apps/api/src/modules/study/study.service.ts` 的调度函数中。后续可根据真实学习数据调整：质量系数、逾期惩罚、重点巩固阈值和最大间隔；也可将 `consecutiveCorrect`、题型、词义难度和单词熟悉度纳入更精细的模型。
