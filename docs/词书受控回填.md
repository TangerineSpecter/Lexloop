# 词书受控回填

## 升级路径和边界

API 启动会扫描词书，词条通过 `createMany(skipDuplicates: true)` 导入。新装数据库可读取 v1.27.152 源词书的 6 词 / 12 字段；已有库不会因此更新。本版本提供独立运维命令，让已有安装在**预览后主动应用**同一已核对批次。不是开机自动回填，不新增公共 HTTP 写接口，也不要求运行整套应用/Worker。

部署镜像包含 `dist/vocabulary-corrections.js`。先按原升级流程应用 Prisma migration（新增 `VocabularyCorrectionAudit` 审计表），再在 API 容器工作目录执行命令。命令使用该实例的数据库连接；开发回归只使用临时 PostgreSQL，未对生产执行任何命令。生产 apply/restore 尚未执行；发布代码不代表授权写入生产，执行前仍须另行核对该实例的操作授权与预览。

```sh
node dist/vocabulary-corrections.js preview
node dist/vocabulary-corrections.js apply <刚才预览返回的token>
node dist/vocabulary-corrections.js restore-preview
node dist/vocabulary-corrections.js restore <恢复预览返回的token>
```

本地开发可用 `node -r ts-node/register src/vocabulary-corrections.ts preview`。不要把数据库 URL、密码或环境文件粘贴到输出/版本库。预览包含候选词和当前字段值，应作为该实例的运维记录保管。`apply`/`restore` 需要预览令牌；操作前数据库有变化会拒绝旧令牌，应重新预览。网络中断时结果可能未确认，先预览审计状态，不假定操作未发生。

## 什么会被修改

批次固定为 `daily-2026-11-03-v1`，编译内容严格对照已核对的 [来源 manifest](../data/vocabulary-corrections/2026-11-03/manifest.json)，只包括此前 12 个字段。派生数据沿用 Wiktionary contributors / CC BY-SA 4.0，归属页和源工作簿归属表不变。

只处理规范词面及原词面完全匹配、类型 WORD、关联 `通用/日常生活单词.xlsx` 且词书为无所有者 SYSTEM 的词条。个人词条、错来源和多词拼接不处理。只有 SQL NULL 可以填入；空字符串、`无` 等非 NULL 值也保留。已有非空值一律不覆盖。

旧模型没有完整编辑来源账本，因此进一步要求 `createdAt === updatedAt`。任何已记录的编辑，包括有意清空字段，都会整词跳过。该保守规则可能遗漏可补内容，但不会为了提高覆盖率绕过保护。绕开应用直接 SQL 修改且不更新时间的历史行为无法从旧数据中可靠识别，不能声称能检测这种修改；预览应由实例维护者核对，必要时保留整个批次不应用。

预览给出 `actions`、逐词 `reason`、待改词数/字段数及 token。常见原因：

| reason                         | 处理                           |
| ------------------------------ | ------------------------------ |
| ready                          | 下次显式应用将补这些 NULL 字段 |
| missing-word / source-mismatch | 未找到或来源不匹配，不改       |
| edited-word                    | 旧词条有编辑时间痕迹，不改     |
| no-empty-fields                | 无待补字段，新装通常如此       |
| already-applied                | 此批已应用，不再写入           |
| restored-do-not-reapply        | 此批已恢复，保留恢复决定       |
| edited-after-apply             | 回填后有修改，恢复时整词保护   |

## 一致性与恢复

应用和恢复均使用 SERIALIZABLE 事务、批次 advisory lock 和目标词条行锁；应用前重算预览令牌。词条修改和审计记录同一事务提交，任一写入失败全部回滚；同一有写入预览的并发应用只允许一个提交，另一个需要重新预览。不会静默重复执行过期操作。

词条行锁与来源关联检查的保证不同：用户编辑若先取得词条锁，回填会在等待后因序列化冲突失败；回填先取得锁时，用户编辑等待回填提交后再执行，最终保留用户值，后续恢复不会覆盖它。来源关联行没有被锁定，检查基于本事务快照；快照读取后的解除关联可以与回填都提交，逻辑上排列为“先回填、后解除关联”，即使解除关联的物理提交较早。SERIALIZABLE 不等于拒绝所有并发修改，也不保证提交时仍存在该关联。若要求维护期间来源完全不变，维护者应另行安排操作窗口，不能依赖本工具提供这种排他保证。

每词审计保存前后字段和更新时间；恢复只在整词当前快照仍等于回填后快照时执行，只还原本批实际改动的字段。回填后用户修改任何字段或更新时间，整词保留，不强行恢复。审计保留 RESTORED 状态，重跑应用不把已恢复内容再填回去。删除词条不会级联删除审计；重建词条使用新 ID，不借用旧恢复记录。恢复不是清空整张词表，也不撤销学习行为。

服务只写 `VocabularyWord` 和 `VocabularyCorrectionAudit`；不修改关联、学习进度、SRS 日期、作答记录或历史题目快照。新装继续使用源文件导入，已有安装经此命令才产生回填；此次开发未连接线上库，不能给出线上实际覆盖率。

## 扩大内容覆盖的研究结果

`node scripts/vocabulary-coverage-inventory.mjs` 按当前源 SHA 输出可重复的只读盘点：1,177 行、缺释义 1,109；其中 13 个独立词面候选、1,096 行需词边界核对。候选不是已审词义，不按词频排名。

- 可优先逐词核验 separated、widowed、cooked、engaged、married、ovation、nonstop、toward、bang、drone、wale、lcd、fiance。婚姻状态与分词、名词与动词、缩写和可疑拼写必须结合词书邻行确定，不能只按词面取第一个义项。
- 已重新查看 [widowed](https://kaikki.org/dictionary/English/meaning/w/wi/widowed.html)：包含形容词和动词，需要选择婚姻状态义；页面没有适用 IPA 就继续留缺。[ovation](https://kaikki.org/dictionary/English/meaning/o/ov/ovation.html) 的第一义项是古罗马仪式，日常语境通常需核对后续义项，不能机械取第一项。这两项本轮尚未发布为补齐数据。
- 地区发音可研究 [CMUdict](https://github.com/cmusphinx/cmudict/blob/master/LICENSE) 美式后备，但必须保留许可，并对音素到 IPA 的转换及重音、变体做测试；不能复制到英音栏，本轮未导入。
- 多词行需先恢复可靠的词条边界和词书位置映射，再考虑释义。直接拆空格会破坏短语及历史关联；不对已有学习库批量拆词，不把未证实分词结果纳入自动回填。

本轮新增可回填能力，不新增词义条数；源缺口仍为释义 1,109、英美音各 1,117。以后每批需独立来源/许可/义项核验、快照与不可变批次 ID，不能修改已发布批次以偷偷扩大回填范围。
