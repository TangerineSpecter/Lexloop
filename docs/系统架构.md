# Lexloop 架构与技术栈

## 目标

Lexloop 是面向成人自学者的英语闭环学习平台。第一阶段先交付可运行的账户、数据、任务与 AI/RAG 基础设施；词书、复习算法、题库和报告属于后续业务迭代。

## 系统边界

```text
浏览器 / PWA
    │
    ▼
Next.js Web ───────────────► NestJS API ─────► PostgreSQL + pgvector
                                  │                   │
                                  │                   └── 业务数据、学习事件、AI 审计、RAG 知识块
                                  ▼
                            Redis + BullMQ ◄──── 独立 Worker
                                  │
                                  ▼
                         S3 兼容对象存储（本地 MinIO / 外部 NAS MinIO / 腾讯 COS）
```

## 技术选型

| 层级         | 技术                                                     | 用途                                               |
| ------------ | -------------------------------------------------------- | -------------------------------------------------- |
| Monorepo     | pnpm workspace + Turborepo                               | 统一管理 Web、API、Worker 与共享包                 |
| Web          | Next.js、React、TypeScript、Tailwind CSS、TanStack Query | 响应式用户端、PWA 元数据、登录与学习界面           |
| API          | NestJS + Fastify                                         | REST API、OpenAPI/Swagger、鉴权、限流与业务模块    |
| 关系数据     | PostgreSQL + Prisma                                      | 用户、令牌、学习事件、内容与审计数据               |
| RAG 检索     | PostgreSQL `pgvector`                                    | 知识块与嵌入向量；首版无需独立向量数据库           |
| 异步任务     | Redis + BullMQ + Node Worker                             | 报告聚合、导入、向量化与 AI 长任务                 |
| 文件对象     | S3 兼容 API                                              | 音频、图片、导入文件和后续 AI 素材；本地默认 MinIO |
| AI           | Provider Adapter                                         | 服务端持有密钥，统一生成、嵌入、结构化输出接口     |
| 本地基础设施 | Docker Compose                                           | PostgreSQL、Redis、MinIO                           |

## 已实现能力

- 邮箱密码注册、登录、JWT access/refresh token 刷新、`USER` / `ADMIN` 角色边界；空用户库中的首个注册账号自动成为管理员，后续账号默认为普通用户。
- API 健康检查、Swagger、CORS、全局参数校验与限流。
- PostgreSQL 初始迁移：用户、刷新令牌、学习事件、AI 调用审计、RAG 知识块及 `vector` 字段。
- BullMQ 示例任务和独立 Worker。
- 内置词表启动时幂等导入 PostgreSQL；词书、词条、用户词书和词条学习进度均由 API 管理。
- 个人生词本可按所属词条分页读取当前用户的真实作答轨迹，使用已保存的题目快照；旧记录缺少快照时明确标记，不从当前词典回填。该只读查询不写入作答、掌握度或复习排期。
- 今日学习目标保存在用户资料中。进度并入既有 `/reports/streak` 和阶段统计已经读取的连续学习证据，不另建学习事件。到期词列表附带已有的上次复习、下次到期和计划间隔，供页面说明原因。独立单词增加 `due` 来源，最多 12 个到期词。学习计划完成后的错题回炉只在浏览器内重做已揭晓的错题，不第二次提交作答。学完小结、连击里程碑和复习队列说明都在浏览器里用已返回的计划、连续天数和到期字段计算。近几日到期数量和可练薄弱词数量随 `/vocabulary/dashboard-words` 返回，薄弱词快练仍创建普通独立单词计划并走 `mistakes` 选词。
- 学习计划、单词答题结果与动态复习排期由 API 持久化；Web 仅通过 API 创建计划、提交结果和读取学习中/待复习列表。复习间隔结合正确率、历史间隔、逾期、复习次数和延期次数计算，单词掌握仍由用户手动确认。分组提交在数据库事务内原子领取未完成题目；同一用户重复提交已完成分组只返回已保存结果，不重复累计作答、连续答对或复习排期。已完成计划会按用户返回当前下次复习日期和活跃题型薄弱项（当前状态，非计划完成时快照）；未完成题目不公开这些状态。未提交题目的答案、解析和提示由统一服务端边界移除；单词匹配题只返回打乱后的配对释义和提示，冗余选项固定清空。学习历史可按需读取单份已完成计划的逐题复盘，只在已提交分组中返回该用户保存的选择、正确答案与解析；此读取不新增答题或复习记录。错题列表支持按单词、当前显示释义或词书名称搜索；服务端先在当前用户与状态/题型筛选范围内匹配、聚合和排序，再分页，搜索不会只查当前页。读取计划总结和错题列表不会写入答题、排期或薄弱项记录。
- AI 学习计划采用“先创建、后生成”的状态流：API 先持久化 `GENERATING` 计划，普通计划创建在数据库事务内按用户加 advisory lock，再检查已有计划并写入，避免多个 API 实例的并发请求为同一用户重复建计划；Web 等待创建响应期间禁用按钮且阻止重复点击。预习生成先查找账号可复用的公共缓存；全部命中时无需选择模型，只有缺失组需要生成时才检查用户模型，模型未选时计划明确失败并可直接打开设置后重试。生成领取使用 `generationStartedAt` 作为数据库栅栏；超过 10 分钟的任务可被重新领取，但只有仍持有当前领取时间戳的请求能原子提交缓存、题目和计划状态，迟到的旧成功或失败结果不会覆盖新一轮结果。正在生成时，计划会持久化 `PREPARING`、`WAITING_PUBLIC_CACHE`、`WAITING_MODEL`、`VALIDATING`、`REPAIRING`、`SAVING` 六种服务端阶段；等待并发请求准备相同公共材料时显示 `WAITING_PUBLIC_CACHE`，不误称正在调用模型。Web 用计划所属用户的状态接口续读阶段和起始时间，阶段来自实际服务端步骤，不提供伪造百分比或模型内部进度。关闭预习窗不会取消已经提交的生成，重新打开可继续查看阶段；状态轮询只查询计划状态，失败时采用退避且标为“当前结果未知”，不会据此发起新的模型生成请求。无歧义的空白格式只在本地规范化；单题结构校验失败时保留其他已校验内容，并允许整个计划最多发起 3 次局部修复请求，不按题目数乘倍；单次请求最长 90 秒，单个计划的累计模型请求时限为 6 分钟，预算耗尽后不会再发请求。生成成功进入 `ACTIVE`，失败保存经白名单处理的错误摘要并允许重试。生成内容包括随机分组、短阅读材料、逐句翻译/简化文本与逐词练习题。
- AI 阅读材料与题目按完整分组写入 `StudyContentCache`。只有整组词条都来自无所有者的 `SYSTEM` 词书时才允许进入公共缓存；个人词书材料只写入所属学习计划快照，不参与跨账号复用。计划生成按现有选词与到期复习规则确定目标词，再优先复用签名和题型匹配、当前题目尚未作答或最新作答错误的启用公共分组；全部候选均已答对或没有合格候选时才生成新内容，不另设熟练度阈值或修改 SRS。历史缓存只有能从关联计划词条证明来源全部为公共系统词书时才保留为可复用公共材料；个人或失去来源关联的记录会被隔离停用，材料和已生成计划快照仍保留。管理员可按状态、模式、日期、文本、精确目标词及是否存在负面评价（任一题目快照）筛选公共材料。目标词筛选按 ASCII 空格、制表/换行、NBSP（U+00A0）和全角空格（U+3000）折叠并忽略大小写后做完整词面匹配，可与其他筛选组合，且在服务端分页前执行。`wordOccurrences` 为对象时（包括空对象）只以该快照映射为准；字段缺失或类型异常时才回退到题目快照关联的系统词书词条。若旧关联缺失、已删除或词条后来改名，筛选无法保证还原当时的词面；目标词筛选针对公共材料，不返回用户身份。列表使用 offset 分页，数据并发变化时不保证跨页属于同一快照。全文搜索仍独立保留。列表分开显示当前材料题目与历史快照的赞踩数，题目详情只显示与当前材料指纹一致的评价，负面原因也按当前题目显示。历史快照中有差评时，可在折叠详情查看最近 10 道旧题及其聚合赞踩数、负面原因和最近评价时间；界面同时标明它们不计入当前题目票数。管理员可逆停用/恢复；学习者只能在完成对应公共题目后提交、修改或撤回自己的赞踩，评价关联到公共缓存 ID 和题目快照指纹，不写入作答、掌握度或复习排期。撤回使用可空 `withdrawnAt` 标记保留原投票行但不再计入反馈展示与管理员聚合；重新评价会重新激活同一指纹的唯一记录。`hitCount` 记录后续缓存命中，不包括最初创建。
- 同一精确公共材料签名由 `StudyContentGenerationClaim` 短租约跨 API 实例协调。租约只保存签名哈希、随机 owner token 和时间；生成期间每 15 秒续租，成功时与计划/材料写入同一事务释放，崩溃后最多在 45 秒租约到期后接管。持锁失败的请求先放弃部分锁再等待，等待最多 100 秒且计入计划 6 分钟总预算；供应商或内容校验失败会为失败前已开始等待的请求保留 15 秒冷却，避免并发重试风暴；失败后新发起的显式重试可以立即继续。等待超时或冷却都不会发起模型请求。等待完成后重新核对公共缓存、精确签名、题型与该用户的最近作答，再决定复用或生成。正常缓存命中与未命中原因只以固定代码和 allowlist 文案记为 `info` 级结构化事件，不写用户、词条、材料或答案；管理员错误日志默认只列 `error`，可用 `GET /api/v1/admin/system-logs?severity=info` 查看这些观测。实际等待超时、冷却拒绝与租约失效仍作为安全诊断的错误日志，不混入正常缓存观测。info 事件按固定代码聚合，计数表示产生该观测的计划次数，不是节省的 token 数。
- `study`、`content`、`mistakes`、`reports`、`rag`、`ai` 模块的稳定入口。
- `practice` 模块提供每日输出、易混词对比和每周处方。输出快照与提交持久化，BullMQ `practice-output` 队列由 Worker 执行模型调用；API 模块中的业务服务校验反馈，并在同一事务写入结果、错题、答题、复习排期和学习事件。每个任务使用只覆盖单份提交、15 分钟过期的随机 capability，数据库只存哈希；Worker 在现有 headless Nest 进程内领取短期处理租约并复用加密模型适配器，不开放任务上下文 HTTP 接口；密钥不进入浏览器、队列或作答记录。对比题由服务器判分，每周处方由近 7 天的聚合证据和当前薄弱项确定性生成。
- `learning-lab` 模块统一提供个人生词精读和语法专项，复用个人词书与每日一句收藏。API 保存用户输入快照并将生成任务交给现有 headless Worker 的 `learning-lab` 队列，使用 capability 与数据库租约隔离重试；公开响应在交卷前过滤答案，交卷由服务端幂等判分并写入学习事件。语法依据来自当前账号的输出批改、场景语法纠错和专项错题。详见 [生词本与精读语法专项](生词本与精读语法专项.md)。
- `micro-stories` 模块提供无需模型等待的连续短故事：用户先提交自己的理解再看到参考解析，自行标记有偏差的内容后按间隔回顾。解析揭晓后可将人工选定的重点表达收藏到本人个人生词本，复用原有语境保存与动态复习；此操作不改变故事进度或偏差卡。服务端保存当前进度和偏差卡，完成一段写入学习事件。详见 [一分钟微故事](一分钟微故事.md)。
- 错题按“用户 + 词书单词 + 题型”聚合为薄弱项；答错自动激活，连续答对两次自动纠正，可生成锁定原薄弱题型的新变式专项。同一账号的未完成薄弱项专项仅在词单完全相同时幂等复用；不同词单会明确冲突，不静默丢弃用户的新选择。
- 待巩固页的状态、题型、已应用搜索词和页码由仪表盘在内存中按当前账号暂存，离开页面去学习再返回时恢复筛选；刷新页面会回到默认筛选，不持久化到浏览器或服务端。重新进入会重新加载错题，所选词条不会跨页面恢复，避免把过期选择带入新专项；切换账号也不会显示前一账号的筛选状态。
- 学习报告分为“阶段复盘”和“学习生涯”：阶段复盘支持近 7 天、近 30 天和近 1 年，综合单词答题、正式测评和旅行场景计算学习日；学习生涯的累计学习日合并单词答题、已完成计划、场景、测评和用户自己的学习专项事件，同一自然日不重复计数；累计学习日与已逾期复习按请求中的 IANA 时区归日，Web 使用浏览器时区；旧客户端未传时区时保留 API 进程默认时区。学习生涯汇总词汇记忆、CEFR 五维能力、测评/场景能力快照、薄弱项与实战技能。统一学习历史流按完成时间合并学习序列、正式测评和旅行场景。历史界面用不透明游标续读，按用户范围和完成时间组合索引查询，并限制每类来源的候选数，避免越往后翻越加载更大的记录前缀；服务端仍接受原有数字页参数供旧客户端兼容。游标页不是跨请求快照：新完成且排序在当前游标之前的记录，需要重新加载第一页后才会显示；已有记录的完成时间不变时，继续加载不会重复显示。下一页请求失败时保留已加载记录，并通过相同游标重试。索引迁移只新增索引、不改写既有学习记录，使用普通 `CREATE INDEX`；生产环境的锁等待与迁移耗时未实测，不能由隔离测试或合成查询耗时推断。确定性规则始终提供建议，用户可按需调用所选模型生成带输入指纹缓存的 AI 学习分析。
- “学习中”和“已掌握”个人词汇档案支持 `pageSize` 与不透明游标续读；每页最多 100 条，Web 默认加载 50 条并明确显示服务端总数。每次请求在同一可重复读事务中读取当前页和总数，使该页与计数一致。为兼容旧客户端，不带分页参数仍返回原数组；分页请求按各自稳定排序读取，游标绑定当前账号并拒绝跨档案/跨账号复用。不同页之间不是共享数据库快照：续读期间新插入且排序在当前游标之前的词不会出现在已开始的链中；“学习中”词的下次复习时间也可能因答题而变动并跨过游标。要查看最新排序，应重新加载第一页。删除已掌握词后，界面同步更新当前已加载列表和总数，并刷新该账号的学习中档案。下一页失败会保留已加载词条并用同一游标重试。迁移仅新增支持索引，不回写词条、作答或掌握记录；隔离测试验证已有行保留，但生产执行普通 `CREATE INDEX` 的锁行为和耗时未经测试。
- Tutor API 在服务端解析学习分组或错题上下文，提供持久化流式会话、每日原子配额和 AI 调用审计；未提交题目的答案不会进入模型上下文。
- AI 未配置密钥时安全拒绝调用；已通过服务端 Provider Adapter 接入 DeepSeek，并兼容任意 OpenAI Chat Completions 端点。Provider 的认证、限流、地址和服务端错误由 API 归类为不泄露密钥的用户提示，不直接透传原始错误体。管理员可在系统设置维护模型，模型 API Key 使用 `AI_CONFIG_ENCRYPTION_KEY` 经 AES-256-GCM 加密后保存，Web 与管理列表均不获取明文。普通用户通过受 JWT 保护的接口仅能取得、选择系统添加且已启用的模型，选择存储在用户资料中并由服务端用于后续调用；默认使用 `https://api.deepseek.com` 和 `deepseek-v4-flash`，可由 `AI_BASE_URL`、`AI_MODEL` 覆盖；浏览器只能调用 API，密钥不会下发到 Web。
- 分组阅读的单句改写、目标词造句和先译后看反馈由学习者主动提交后同步调用其 JWT 用户已选 Provider。它们返回形成性建议，不写作答、学习事件或复习排期；失败不存储学习者原文，页面仅保留当前 React 草稿供手动重试。翻译反馈只发送英文原句和学习者中文译文，参考译文留在 Web 端。
- `travel` 模块独立承载 CEFR 文字测评、每日旅行练习计划、18 个版本化场景蓝图、场景会话与能力证据。场景蓝图和客观测评题在启动时幂等写入数据库；AI 只生成场景变体与自由表达评分，不能改变服务端保存的任务目标或直接决定最终等级。
- `adventure` 模块提供单机回合制学习 RPG。地牢路线、题目快照、职业资源、伤害、掉落、失败扣损和楼层解锁均由 API 权威结算；浏览器只提交答案与幂等行动 ID。开始探索时，用户可为本局选均衡、主动回想或语境组句题型配比；选择随本局快照保存，旧快照按原均衡题序读取，不改变复习排期或掌握门槛。进行中的地牢读取会附带该账号本局最近一次已保存的题目、回答与反馈，供页面刷新后续练；浏览器按账号保存本机 run ID，终局响应丢失时可通过用户校验的只读接口恢复结果，确认返回地图后清除该标记。结算读取还会按账号读取本局已有的、非临时且分数未达标的行动，供玩家自愿先回想自己的答案、再展开参考答案；不重新评分、不调用模型、不创建复习或奖励记录。行动反馈与作答记录在同一行动行中保存当时题干、参考答案、词义和词条，以及是否无法判定；复盘只使用行动自身快照，不从当前房间或词库回填，因此题目顺序/词义更新不会替换历史内容。缺少题干或参考答案的旧行动只计入不可回放数量。低于通过阈值但无法判定的短回答或临时模型反馈会单独标注；旧记录未保存判断状态时标为未知。读取不新增学习记录。精英、宝箱和首领房在清场事务内确定性生成装备，同一行动重放不会重复掉落；每局第一件装备自动保险，战败删除其余未保险的新装备。选择题只形成识别证据；AI 不可用时自由造句的临时判断不计正确复习或掌握证据。楼层掌握只汇总数据库标记为有效、分数达标的召回/产出证据；同一词必须在不同探索中至少两次成功且包含主动召回或产出，才计入掌握度。
- 冒险职业、技能和装备使用数据驱动目录，首版包含四个基础职业、分支转职与二次进阶；四个基础职业各有一个小幅战斗被动，转职沿用基础职业被动：战士成功格挡且仍受伤时最多额外减免 4 点，法师消耗技能资源并完美命中时额外造成 6 点战斗伤害，游侠同房间连续正确作答后攻击额外造成 6 点伤害，牧师未满生命时答对词块组句或有效评分的自由作答每房间最多恢复 4 点。牧师的词块组句按保存的参考句确定性判定，不需要模型；自由作答仅接受非临时且分数达标的结果，模型不可用时的启发式反馈标记 provisional，不能触发治疗。5 分钟回想路线三道开局题没有组句/自由作答；路线选择会解释这一点，战斗延续时题序仍可能进入后续类型。新探索快照记录被动规则版本；旧探索不套用新被动。被动只改变本局伤害或生命，不改变判题、学习证据、奖励或 SRS。技能目标预留 `ALLY` / `PARTY`，但当前不创建队伍或多人状态。地牢层按默认词书每 12 个词生成，现有词汇进度、薄弱项与学习事件继续作为统一学习闭环。
- 场景回合先持久化带客户端幂等 ID 的用户输入，再通过数据库处理令牌串行化同一会话的模型调用；AI 回复以用户回合 ID 精确关联，结构化回复严格校验成功后与任务进度在同一事务写入。Provider 失败不会生成半截回复，用户可用同一消息 ID 重试。
- 个人生词本（兼容原旅行生词本）仍使用词书、词条和单词进度模型，但词书标记为 `PERSONAL` 并绑定所有者；个人表达使用带用户作用域的规范键，避免修改系统或其他用户词条。收藏后立即进入现有动态复习链路，删除时清理无引用的个人词条。

## 当前存储策略

每日一句由独立 Worker 进程组中的无 HTTP Nest 上下文调度与生成，复用 API 的 Prisma、加密模型配置和 AI 适配器。API 仅处理用户隔离的读取、已读、收藏、反馈和失败重试入队；首页请求不启动生成。管理员全局开关持久化到 `SystemFeatureSetting`，关闭时隐藏首页入口并在定时扫描、生成预留与重试入口共同阻止新生成，历史和收藏保留。每日北京时间 06:00 起检查，未读保留、当天已读不补发；数据库锁、日期唯一键与未读部分唯一索引共同控制生成量。完整规则与数据流见 [每日一句](每日一句.md)。

每日自动学习计划由同一无 HTTP Worker 上下文中的独立 BullMQ 队列处理，避免计划生成阻塞每日一句。管理员设置全局默认关闭，按配置的北京时间处理当前日期；停机期间不补生成已错过的日期。每个用户和北京时间日期有唯一运行记录，计划本身也以用户/日期唯一键关联；计划创建继续使用现有用户 advisory lock，材料生成继续使用原 10 分钟领取栅栏。已有未完成计划时跳过；自动计划使用用户默认新词数、普通分组模式及现有默认到期复习选择（最多 40 个），不会读取并不存在的持久化模式或复习数量偏好。没有可用模型或可练词时跳过且不创建计划。失败最多重试一次并复用同一计划 ID；生成不会产生作答、学习事件或复习排期，也不会预先把新词加入“学习中”进度；用户首次提交该组答案后才在同一事务内建立新词进度并保存作答。管理员关闭后，尚未开始的排队项会取消，已经开始的模型请求可能完成。运行摘要仅显示各状态和安全原因计数，不显示用户标识。每日运行记录保留 90 天。管理员启用会触发全部符合条件用户的模型调用并可能产生费用；默认关闭，开发和测试不实际启用生产配置。详细规则见 [每日自动学习计划](每日自动学习计划.md)。

本地 `dev.sh` 始终启动项目内的 MinIO，保证离线或在外网环境也可完成开发。生产或固定环境可将应用的 S3 endpoint 指向 NAS 上独立部署的 MinIO；应用代码应只依赖 S3 兼容接口，不依赖 MinIO 专属能力。

当前项目尚未实现实际文件上传/下载服务；MinIO、`MINIO_ENDPOINT` 等变量是为对象存储模块预留的基础设施。实施上传模块时，应由 API 生成短期预签名 URL，浏览器直传对象存储，数据库仅保存对象键、媒体类型、大小和业务关联。

管理员「系统设置 → 系统日志」查看的是 Lexloop 应用诊断事件，不包括 Docker、Caddy、操作系统或数据库日志。API 记录未处理的 5xx 与管理员主动测试模型失败，Worker 记录已有队列的失败尝试、最终失败和队列连接错误；预期的 4xx 不作为系统故障统计。日志采用独立文件，不写数据库：API 与 Worker 分别写入进程分片，共用生产 Compose 中定义的 `system_logs` 卷；开发环境默认写入 API 工作目录下的 `var/system-logs`，可用 `LEXLOOP_LOG_DIR` 覆盖。该 Compose 卷配置尚未通过生产部署验证。

写入前只保留稳定错误码、HTTP 状态、路由模板、请求方法和有限的状态说明，不保存异常原文、堆栈、密钥、Cookie、请求正文、学习者输入或任务标识。管理员查询时按 `APP_TIMEZONE`（默认 `Asia/Shanghai`）的自然日合并事件；同类计数和最近明细只计算当前所选日期范围。按默认 14 天保留；API、Worker 各自最多使用 49 MiB 事件文件和 1 MiB 丢弃计数文件，页面显示合计 100 MiB 上限。空间不足时新事件不写入，并尽力保留丢弃数量；日志不可用不会递归写日志。CSV 导出会按所选日期范围重新计算，单条导出只包含该组的聚合结果和范围内最新明细。清空通过轮换日志代数执行，只影响已有应用日志，不删除学习数据；清空后的新事件仍继续记录。

管理员模型「测试连接」仅由用户主动点击后，向所选的已保存配置发送一次固定的短 JSON 请求；编辑中的草稿不会被测试或自动保存。结果分别说明端点响应、认证、模型接受和结构化生成状态；不自动重试。真实供应商请求可能产生费用，自动化验收只使用 mock，不证明实际供应商兼容性。

MiniMax 语音合成默认关闭。管理员在系统设置中保存区域、模型、音色和经 AES-GCM 加密的 API Key 后，已登录用户点击单词或句子发音时，API 先检查该账号自己的缓存；缓存未命中或文件丢失时，页面会说明文本将发送给 MiniMax 且可能产生费用，只有用户再次确认才发起一次请求。没有后台预生成或自动重试。模型响应只接受有界大小的音频，不保存原文或请求正文；数据库仅保存用户 ID、带服务端密钥的文本/参数指纹、音色参数和随机文件名。音频文件位于 API 专用的 `tts_audio_data` 持久卷，文件按随机名原子写入且目录/文件权限收紧；下载接口同时校验登录用户归属、文件长度及 SHA-256。相同账号和参数的并发请求使用数据库租约合并；API 在调用供应商前条件续租，MiniMax 客户端在实际 `fetch` 前再次依据绝对到期时间检查租约，剩余时间扣除安全余量后决定请求超时（最多 45 秒）；余量不足时不发送请求并退回预留用量。若续租后进程暂停到租约过期且被其他请求接管，旧请求恢复后不会发起供应商调用。预留用量的退款由同一审计记录的条件状态变更作为一次性回执，并与原用户/日期的原子扣减处于同一数据库事务，避免重复退款覆盖并发预留。结果提交仍受 owner token 栅栏保护。请求一旦发出，网络中断、超时或进程暂停仍不能证明供应商是否已完成或计费，系统不会自动重试；账号日调用次数、字符数、单条音频大小、个人缓存容量和缓存期限均有上限。缓存只按账号隔离，不在账号间共享。进程在数据库提交前意外退出留下的孤儿音频和临时文件会由 API 清理器按批扫描，文件至少保留 24 小时后才清除；每批目录扫描最多检查 2,000 项。该卷是可重建缓存，不包含在现有远端备份中；仅恢复数据库或缓存文件丢失时，首次再次点播会先提示文件缺失，再由用户确认重新生成。当前 Compose 仅为单个 API 服务挂载该卷；多 API 实例需共享一致的受保护文件存储后才能复用缓存，不应直接横向扩容此本地目录方案。自动化只用离线/mock，不代表真实 MiniMax 账号、指定音色或线上网络已验证。

管理员可为模型配置可选温度（0–2）。留空时，自定义 OpenAI 兼容模型不发送 `temperature`，由供应商/模型使用其默认值；DeepSeek 保留各功能原有的调用温度。显式温度由模型配置统一应用到连接测试、学习生成、导师回复和异步批改/学习内容生成。新字段为可空值，既有模型迁移后保持为空，不修改密钥或重新测试配置；模型可能只接受范围内的部分值，管理员应按对应供应商文档设置。连接测试仍保留 JSON `response_format`，以确认结构化生成能力。

## 生产部署与更新边界

生产环境使用单机 Docker Compose，Caddy 作为 Web/API 同源入口。应用镜像由服务器从受信任的 `master` 稳定 tag 本地缓存构建，PostgreSQL、Redis 和 MinIO 不直接暴露到宿主机网络。

系统更新由独立 updater 执行。管理员从 Web 发起更新，API 只负责角色、密码复验和固定 DTO 校验，通过 Unix Socket 请求 updater；只有 updater 持有 Docker Socket、Git worktree、生产配置和备份目录权限。updater 不监听 TCP、不接受任意仓库或 shell 参数，并在 API 容器重启期间独立保存任务状态。

安装完成前同时验证应用容器、updater 健康检查与 API 到 updater 的连接。updater 异步拉取 Git 并合并并发检查；部分切换失败也触发应用镜像恢复。应用更新成功后，由具有相同部署权限的一次性辅助容器替换 updater，避免容器停止时杀死负责自更新的 Compose 进程。重新运行安装脚本时，updater 以经过版本校验的安装环境校正已保存的运行版本。

版本身份由 SemVer 与 commit SHA 共同组成。同版本 tag 移动只有在新提交是当前提交的后继提交时才允许更新；分叉或回退提交一律拒绝。部署流程和恢复方式见 [生产部署与更新](生产部署与更新.md)。

## MiniMax 文本模型

管理员提供方改为可扩展下拉，新增 MiniMax，使用中国站 `https://api.minimax.cn/v1/chat/completions` 与 `MiniMax-M3.1-Flash` / `MiniMax-M3`。枚举迁移只增加 `MINIMAX`，不转换现有自定义 OpenAI 配置，不读取或重加密旧密钥；编辑密钥留空仍保留原值。

API 和两个异步生成 Worker 共用协议适配：MiniMax 不发送温度、top_p 或未声明支持的 response_format，继续使用 JSON 提示与各业务本地解析校验。思考与最终文本分离；浏览器和业务解析只收到最终内容，流式转发过滤 reasoning_content。默认使用 low 思考深度（仅支持该参数的模型生效）；MiniMax 的 max_tokens 与 max_completion_tokens 均须为 1–32768 的有限正整数，否则请求在访问供应商前以 400 拒绝；同时提供时两者都校验，max_completion_tokens 优先。未显式指定 max_completion_tokens 时，输出预算为 max(16384, max_tokens)，预算包含思考。其他提供方的 token 参数保持原有兼容，不套用此上限。HTTP 200 的业务失败与 length 截断明确拒绝，不把不完整 JSON 当作完整结果；适配层不增加自动重试，已有业务补救仍受其总次数预算限制。普通 JSON 响应和单个 SSE 缓冲上限为 2 MiB。连接测试仍只在用户主动点击后运行。

协议依据：[MiniMax OpenAI 兼容接口](https://platform.minimax.io/docs/api-reference/text-chat-openai)。验收仅使用 mock，不调用真实供应商、不证明线上账号或模型连通性。

### MiniMax 流式完成校验

以官方 OpenAI 兼容响应的 `finish_reason: stop`（文本完成）或 `tool_calls`（交给工具）作为完成证据；`length` 和未知终止原因均失败。参考 [Chat Completion](https://platform.minimax.io/docs/api-reference/text-chat-openai) 与 [Tool Use](https://platform.minimax.io/docs/guides/text-m3-function-call)。每个已观察到的 choice 都须结束；仅收到 `[DONE]`、空 EOF、半个 SSE 帧或未完成的 choice 都不能算成功。已确认 finish_reason 后允许上游直接 EOF，适配器统一在校验完成后输出 `[DONE]`。

公共 chat SSE 若响应中途失败，通过 `data: {"error":{"code":"STREAM_INCOMPLETE",...}}` 标记失败，不输出 `[DONE]`，错误文字固定且不泄露供应商异常；已经送出的文字可能不完整。Tutor 继续使用现有 `event: error` 协议，将部分内容保存为 FAILED，审计也标记失败，不发送 done。其他提供方的正常流式数据不变。

### 渐进练习公共材料校验补充（2026-11-03）

FOUNDATION/CONTEXT 的每个含目标词的句子都必须满足阶段长度，不能通过另一句合格目标句掩盖越界句。生成结果与公共材料命中共用同一校验，旧缓存不批量改写；不合格的命中被跳过，按既有限次生成/修复路径替换。

公共复用单位仍是同阶段、版本、词义、题型和目标词匹配的一整组材料（阅读句子与配题），不是从不同材料自由拼题。渐进模式每组一个词，单组替换不影响其他组；隔离 PostgreSQL 测试覆盖跨学习者复用、不合格组单独重新生成和未作答时不产生复习证据。个人词书与普通模式的隔离规则保留。

本地确定性校验不能认证 CEFR 难度、词义/词性语义正确性、原创性或 TRANSFER 真正需要两条跨句证据；这些仍是生成提示要求和人工评估项。本轮没有调用真实模型，也没有把结构测试当成实际学习效果证明。
