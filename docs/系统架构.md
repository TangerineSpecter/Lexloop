# Lexloop 架构与技术栈

## 目标

Lexloop 是面向成人自学者的英语闭环学习平台。第一阶段先交付可运行的账户、数据、任务与 AI/RAG 基础设施；词书、复习算法、题库和报告属于后续业务迭代。

## 系统边界

```text
浏览器 / PWA
    │
    ▼
Next.js Web ───────────────► NestJS API ─────► PostgreSQL + pgvector
                                  │                   │
                                  │                   └── 业务数据、学习事件、AI 审计、RAG 知识块
                                  ▼
                            Redis + BullMQ ◄──── 独立 Worker
                                  │
                                  ▼
                         S3 兼容对象存储（本地 MinIO / 外部 NAS MinIO / 腾讯 COS）
```

## 技术选型

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| Monorepo | pnpm workspace + Turborepo | 统一管理 Web、API、Worker 与共享包 |
| Web | Next.js、React、TypeScript、Tailwind CSS、TanStack Query | 响应式用户端、PWA 元数据、登录与学习界面 |
| API | NestJS + Fastify | REST API、OpenAPI/Swagger、鉴权、限流与业务模块 |
| 关系数据 | PostgreSQL + Prisma | 用户、令牌、学习事件、内容与审计数据 |
| RAG 检索 | PostgreSQL `pgvector` | 知识块与嵌入向量；首版无需独立向量数据库 |
| 异步任务 | Redis + BullMQ + Node Worker | 报告聚合、导入、向量化与 AI 长任务 |
| 文件对象 | S3 兼容 API | 音频、图片、导入文件和后续 AI 素材；本地默认 MinIO |
| AI | Provider Adapter | 服务端持有密钥，统一生成、嵌入、结构化输出接口 |
| 本地基础设施 | Docker Compose | PostgreSQL、Redis、MinIO |

## 已实现能力

- 邮箱密码注册、登录、JWT access/refresh token 刷新、`USER` / `ADMIN` 角色边界；空用户库中的首个注册账号自动成为管理员，后续账号默认为普通用户。
- API 健康检查、Swagger、CORS、全局参数校验与限流。
- PostgreSQL 初始迁移：用户、刷新令牌、学习事件、AI 调用审计、RAG 知识块及 `vector` 字段。
- BullMQ 示例任务和独立 Worker。
- 内置词表启动时幂等导入 PostgreSQL；词书、词条、用户词书和词条学习进度均由 API 管理。
- 学习计划、单词答题结果与动态复习排期由 API 持久化；Web 仅通过 API 创建计划、提交结果和读取学习中/待复习列表。复习间隔结合正确率、历史间隔、逾期、复习次数和延期次数计算，单词掌握仍由用户手动确认。
- AI 学习计划采用“先创建、后生成”的状态流：API 先持久化 `GENERATING` 计划，Web 在预习层调用生成接口并禁用挑战入口；结构化内容校验成功后进入 `ACTIVE`，失败则保存错误摘要并允许重试。生成内容包括随机分组、短阅读材料、逐句翻译/简化文本与逐词练习题。
- AI 阅读材料与题目使用账号无关的 `StudyContentCache` 持久化。计划生成按目标词组合优先复用当前用户未答过的缓存分组，仅为缓存缺口调用 Provider；个人计划、作答与复习数据可被清理，公共生成内容不会随用户记录删除。
- `study`、`content`、`mistakes`、`reports`、`rag`、`ai` 模块的稳定入口。
- 错题按“用户 + 词书单词 + 题型”聚合为薄弱项；答错自动激活，连续答对两次自动纠正，可生成锁定原薄弱题型的新变式专项。
- 学习报告分为“阶段复盘”和“学习生涯”：阶段复盘支持近 7 天、近 30 天和近 1 年，综合单词答题、正式测评和旅行场景计算学习日；学习生涯汇总词汇记忆、CEFR 五维能力、测评/场景能力快照、薄弱项与实战技能。统一学习历史流按完成时间合并学习序列、正式测评和旅行场景。确定性规则始终提供建议，用户可按需调用所选模型生成带输入指纹缓存的 AI 学习分析。
- Tutor API 在服务端解析学习分组或错题上下文，提供持久化流式会话、每日原子配额和 AI 调用审计；未提交题目的答案不会进入模型上下文。
- AI 未配置密钥时安全拒绝调用；已通过服务端 Provider Adapter 接入 DeepSeek，并兼容任意 OpenAI Chat Completions 端点。Provider 的认证、限流、地址和服务端错误由 API 归类为不泄露密钥的用户提示，不直接透传原始错误体。管理员可在系统设置维护模型，模型 API Key 使用 `AI_CONFIG_ENCRYPTION_KEY` 经 AES-256-GCM 加密后保存，Web 与管理列表均不获取明文。普通用户通过受 JWT 保护的接口仅能取得、选择系统添加且已启用的模型，选择存储在用户资料中并由服务端用于后续调用；默认使用 `https://api.deepseek.com` 和 `deepseek-v4-flash`，可由 `AI_BASE_URL`、`AI_MODEL` 覆盖；浏览器只能调用 API，密钥不会下发到 Web。
- `travel` 模块独立承载 CEFR 文字测评、每日旅行练习计划、18 个版本化场景蓝图、场景会话与能力证据。场景蓝图和客观测评题在启动时幂等写入数据库；AI 只生成场景变体与自由表达评分，不能改变服务端保存的任务目标或直接决定最终等级。
- 场景回合先持久化带客户端幂等 ID 的用户输入，再通过数据库处理令牌串行化同一会话的模型调用；AI 回复以用户回合 ID 精确关联，结构化回复严格校验成功后与任务进度在同一事务写入。Provider 失败不会生成半截回复，用户可用同一消息 ID 重试。
- 个人旅行生词本仍使用词书、词条和单词进度模型，但词书标记为 `PERSONAL` 并绑定所有者；个人表达使用带用户作用域的规范键，避免修改系统或其他用户词条。收藏后立即进入现有动态复习链路，删除时清理无引用的个人词条。

## 当前存储策略

本地 `dev.sh` 始终启动项目内的 MinIO，保证离线或在外网环境也可完成开发。生产或固定环境可将应用的 S3 endpoint 指向 NAS 上独立部署的 MinIO；应用代码应只依赖 S3 兼容接口，不依赖 MinIO 专属能力。

当前项目尚未实现实际文件上传/下载服务；MinIO、`MINIO_ENDPOINT` 等变量是为对象存储模块预留的基础设施。实施上传模块时，应由 API 生成短期预签名 URL，浏览器直传对象存储，数据库仅保存对象键、媒体类型、大小和业务关联。
