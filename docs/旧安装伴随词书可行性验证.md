# 旧安装伴随词书可行性验证

本轮基于 v1.27.156，对“另建伴随书、不改旧关联”的方案做真实临时 PostgreSQL 验证。结论：**不直接启用伴随书**。它可以保留旧书的 ID，却不能直接满足“不重复误判新词、可停止后续复习、撤销保留学习记录”的完整体验。问题来自现有数据与选词语义，不是环境不可用或操作被拒绝。

本轮只新增可复现探针、只读源盘点并修正盘点统计；没有创建面向用户的伴随书、没有修改生产或已有用户数据，不把审计工具包装成已经交付的旧库修复。没有实际内容升级，因此不单独打补丁标签。

## 实际数据库证据

运行 `node scripts/test-api-isolated.mjs`，其中 `companion-book-safety.integration.spec.ts` 使用随机隔离账号、合成词和完整迁移后的数据库。没有调用模型。四个用例分别证明：

1. **同词跨书会再次算新词。** 原书的 `surname` 已有 5 次作答、4 次正确、未来 7 天才复习；伴随书关联同一个全局 wordId。创建渐进计划仍选择伴随关联，来源为 NEW。原进度保持不变，但用户得到的是另一份学习轨迹。手动 `UserMasteredWord` 则会跨书排除同词，两者不能混称“熟练度”。
2. **退订/停用不等于暂停复习。** 给原关联及伴随关联各建立到期记录，切回原书、移除伴随订阅并设置伴随书 `isActive=false`；渐进计划仍同时选到两个 REVIEW 关联。当前到期查询按用户进度选词，不检查订阅或书是否停用。这是既有跨词书持续复习规则，不能为了伴随书擅自全局改掉。
3. **删除不能充当有历史记录后的撤销。** 在事务内删除伴随书，会级联删除其 `UserWordProgress`、`StudyPlanItem` 及关联的 `WordReviewAttempt`。测试随后主动回滚，并确认全部快照恢复；这不表示已经提交的删除能无损撤销。原书记录不受测试中的伴随删除影响，但伴随学习记录本身也必须保护。
4. **直接追加可保留 ID，但现有版本化导入器不支持增量。** 同 revision 的追加提案被完整映射校验拒绝；换 revision 时返回 preserved，仍不追加。另用直接 Prisma 事务追加一个关联，确认旧关联和旧进度不变，仅证明底层可以追加，不能据此声称现有导入流程已经提供增量更新。

这些用例是当前方案的边界证据，而不是将风险行为认可为期望的产品体验。将来引入伴随功能时，需要改为对应的安全验收测试。

## 内容可用性盘点

`node scripts/audit-daily-companion-sources.mjs` 只读取仓库的 113 本 XLSX，并记录文件 SHA-256、匹配行和字段是否为占位值。本批 36 行拆分得到的 92 个候选词中：

| 观察                         | 词数 |
| ---------------------------- | ---: |
| 在其他完整词面单元格中有匹配 |   89 |
| 至少一处有非占位释义文本     |   84 |
| 存在多个不同释义字符串       |   38 |
| 本轮完成语义/来源许可批准    |    0 |

不同字符串可能是不同义项、格式差异或错误，不等于已经确定存在语义冲突。没有非占位释义的 8 个候选也不应直接作为可练内容上线。该盘点不连接用户数据库、不知道实际安装有哪些词，也不证明其中 84 个词已达到质量或授权要求；本轮不选第一条覆盖、不合并释义、不添加音标。

同时修复旧盘点脚本的计数错误：它把 7 个已审短语和 29 个已审歧义行也算进“未分类”，显示 1,055；现按分类账返回真正尚未审查的 **1,019**，并单列这两类保留行。回归先复现旧值，再验证修复。

## 最小安全实现应满足的协议

以下为下一阶段设计与验收要求，不是现成功能：

- **明确报名而非自动换书。** 需要独立的用户伴随书登记，记录接受的版本、启用/暂停状态和审计批次。旧默认书、旧关联与学习记录全部保留，用户选择是否采用伴随书。
- **保守处理跨书已学词。** 伴随书的新词选择应排除该用户已经在任何书里学习过的同一全局词，单列“已学而跳过”，不复制 SRS 或答题次数。与已有语境不同的义项另作审查，不能仅按词面把所有学习历史合并。此规则只能作用于明确的伴随入口，不擅自改变普通个人语境词书的规则。
- **暂停使用登记状态，不删除。** 暂停只阻止后续选词；需要统一覆盖每日、渐进、专项、自动计划及相关到期预览等实际入口。已生成计划与历史快照保留，界面明确其仍可查看，不能谎称已撤回所有已提交计划。不能仅设置 `isActive=false` 或删除订阅。
- **增量只追加且需逐版接受。** 使用稳定伴随书标识，版本清单保存来源证据和完整映射。新增目标只追加位置；旧关联和个人字段保持不变。预览必须列出重复/已学/缺释义/未审内容，应用使用令牌或快照哈希、事务及幂等批次。不能绕过现有 seed 的不变映射保护来强行续填。
- **恢复按暂停处理。** 有学习记录后不得硬删伴随书或关联。暂停/重新启用保留其真实进度；预览本身不产生记录，事务失败应完全回滚，不依赖事后删除来清理半成品。

当前缺少统一的伴随登记及各选词入口的暂停语义，还需要逐词的内容核验。只增加一本书或一个“撤销”按钮不能满足上述要求。为遵守“不改已有学习记录”的要求，本轮停在可重复验证与实现约束，不在生产试运行，也不把新装 1,245 条映射说成旧库已经更新。

证据目录：`/workspace/lexloop-companion-evidence/`。最终 API 99 文件、566/566 通过、0 跳过；脚本 15/15、API 类型检查与 Nest 构建通过。独立复审确认探针与文档边界准确，未发现提交验证材料的剩余阻断。以上测试通过表示风险已被可重复地观察和界定，不表示伴随功能已经安全实现。
