# 开发与验收

## Web 单元测试

运行 `pnpm --filter @lexloop/web test`，或在仓库根目录执行 `node apps/web/test/run-unit-tests.mjs`。入口会发现 `apps/web/test` 下的 `*.test.mjs` 单元测试，并串行运行它们；`*.browser.test.mjs` 会明确排除，因此不会因缺少浏览器地址而把浏览器用例报告为跳过。没有发现单元测试时入口会失败，避免测试任务空跑。

Web API 客户端回归覆盖请求中断、响应正文读取中断和主动取消：网络不可达时提示检查网络并稍后重试，主动取消保留为取消错误。浏览器回归还验证学习草稿和已创建计划在连接失败后仍可通过现有重试路径恢复；应用不排队或自动重放离线写入。

浏览器回归另行运行下方的 standalone 入口；Web 包的单元测试不会替代真实浏览器验收。

## standalone 浏览器回归

运行 `node scripts/test-web-browser-standalone.mjs`，或执行 `pnpm test:web:browser:standalone`。

脚本先构建 Web，再按当前 Next.js standalone 输出布局准备 `apps/web/.next/standalone/apps/web` 下的静态资源；若有 `apps/web/public`，也会复制并核对。随后检查 standalone 服务入口和构建资源，启动仅绑定 `127.0.0.1` 的临时服务，确认页面引用的 JavaScript 与 CSS 均可读取，再串行运行 `apps/web/test/*.browser.test.mjs`。测试退出或失败时都会停止本次启动的服务。

构建后还会核对 `/` 与 `/dashboard` 的首屏 JavaScript 清单：仪表盘只在确认登录后加载；场景口语、学习历史、统计、待巩固和系统设置模块必须留在独立延迟块中，不得混回两个入口路由。按每个首屏 JS 文件的 gzip 字节数相加，每条路由上限为 150 KB；此指标衡量构建资产体积，不等同于真实网络下载时间或页面交互时延。浏览器回归会挂起首个学习栏目 chunk，验证加载占位、快速离开后迟到代码不触发该页请求；还会阻断另一个栏目 chunk，确认页面显示原栏目和可访问重试，重试恢复所选栏目并保留本机草稿。深链接、普通刷新和前进/后退按各自既有语义检查，不把普通刷新误改成重试恢复。

浏览器还覆盖精读学习闭环：用本地夹具选择目标词、生成阅读、展开译文与讲解，并验证交卷失败保留选择、服务端成功响应前不展示答案或解析、成功后显示得分与历史；桌面 1440px 和窄屏 390px 均检查横向溢出。该用例不连接真实模型，也不证明模型生成内容的语义质量。

环境需要已安装 workspace 依赖、Chromium 和 Node.js。可用 `LAB_BROWSER_EXECUTABLE` 指定浏览器可执行文件。测试使用各浏览器用例中的本地数据夹具；完整 API 数据库回归另用 `node scripts/test-api-isolated.mjs`。

每个浏览器用例使用独立临时 profile，结束时先通过该 Chromium 的 DevTools 地址请求正常关闭，并等待子进程退出。Linux 环境若有 C 编译器，入口会在 `/tmp` 编译一个进程级 subreaper，让 Chromium 意外遗留的后代由本次测试等待回收；临时二进制在结束时删除。超时后只通知该用例创建的浏览器组，不操作 PID 1 或其他进程。没有编译器时会提示并退回进程组清理。
