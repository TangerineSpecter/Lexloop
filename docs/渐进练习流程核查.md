# 渐进练习流程核查

本次核查基于 v1.27.154，使用隔离 PostgreSQL、HTTP 请求与原创固定材料；没有调用真实模型、读取生产数据或修改生产排期。

## 已复现并修复

解锁语境辨析后，用户主动回练短句辨义。在这份计划未完成时，向 `POST /study/progressive-path/plans` 提交 `{}`，原实现将最高已解锁阶段当成切换目标，返回 400。现改为省略阶段时续接已有计划；显式指定其他阶段仍返回冲突。未创建计划时，省略阶段仍选择最高已解锁阶段。

修复前真实 HTTP 回归得到 `expected 400 to be 201`；修复后返回原计划 ID。现有前端继续按钮直接打开计划，通常不会触发此问题；因此不能把这项 API 修复描述成全面改善了前端分级体验。

## 已验证的学习流程

新增 `progressive-stage-flow.integration.spec.ts`，用同一系统词书的同一目标词、两个学习者走完三个阶段：

- 每阶段的目标题型和公共材料分别匹配；三个阶段产生三个不同缓存 ID 和签名。
- 第二个学习者尚未做过对应材料时，整组复用且不调用模型。复用的是阅读与配题，不是拼装独立题目。
- 生成材料不增加答题次数；只有提交才累计正确或错误证据。两个学习者分别全对和全错，正确次数与实际提交一致，均不自动写入手动掌握记录。
- 完成前一阶段后，未到期且没有新词时不能立即创建后一阶段练习；测试推进到期时间后，才以 REVIEW 来源选中该词。创建计划不提前改动排期。
- 已经答错的旧阶段材料在目标词到期后仍能复用；回练不降低已解锁阶段，答对后正确次数正常增加。
- 手动标记掌握的词即使已到期也不再选入；空选词失败不创建计划，也不改动排期。

既有测试另覆盖个人材料隔离、缓存句长/句界/重复结构不合格时只重生成受影响组、重复提交幂等和账号隔离。以上是流程与结构证据，不是学习效果实验。

## 设计边界及后续优先项

1. 阶段是账号级的练习要求，不是每个词的能力等级。当前按完成解锁，答错不降级；选词沿用到期复习与新词规则，每次最多三复习词、两新词。不能据此声称学习者已掌握某个阶段，也不能保证同一批词连续走完三个阶段。
2. 三阶段共享 SRS 调度，保留题型与答题结果，但没有经过校准的跨题型能力估计。本轮不凭题型或句长修改排期间隔，也不添加任意通过率阈值。
3. 最高解锁阶段是默认选择，不是根据近期错误推荐的学习阶段。可考虑增加按阶段展示的练习次数、近期答题情况及回练建议，但应与“已掌握”分开，并说明样本量；需独立设计后成批实施。
4. 缓存选择会排除该用户已答对的精确版本，但生成提示中的“新的语境和选项”不是语义去重保证。当前生成路径不能证明模型不会重新输出旧题，也不能证明推断题确实需要跨句推理；应进一步评估可重复的题目新颖性防护，避免将格式校验描述为语义验证。
5. 本轮不增加内容源，不作 CEFR 认证或学习效果承诺。小范围续练修复与流程回归先保留在开发分支，随后续有价值的体验改进统一审查和发布，避免仅为这项微小修复单独发版。
