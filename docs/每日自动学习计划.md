# 每日自动学习计划

管理员可在「系统设置 → 功能开关」为全部用户启用每日自动学习计划，并设置北京时间执行时间。新设置默认关闭。启用前应考虑符合条件的用户数、所选模型费用和 Worker 容量。

## 执行规则

- Worker 每分钟检查是否到达当天配置时间；时区固定为 `Asia/Shanghai`。只处理当前北京时间日期，不补跑错过的日期。
- 每个用户每天最多有一条自动运行记录。重复扫描、Worker 重启及重复队列消息不会创建重复计划。
- 用户已有生成中或学习中的普通计划时跳过，不覆盖用户预习。已完成的计划不阻止下一日计划。
- 自动计划使用普通分组模式、用户资料中的默认新词数，以及现有默认到期复习选择（最多 40 个）。个别用户的练习模式、词书筛选或本次复习数量没有持久化时，不推断这些偏好。
- 自动准备计划只创建计划与题目快照，不会提前把新词写入用户的“学习中”词汇进度。用户首次实际提交该组答案时，才在同一事务内建立进度并保存作答。
- 没有已启用的用户所选模型或没有可练词时跳过，不创建空计划。跳过与失败原因按安全代码聚合，不保存学习者答案或模型明文错误。
- 计划材料生成失败最多重试一次，并复用原计划 ID。生成不产生答题、完成、掌握或 SRS 证据；自动计划的新词学习进度等到用户实际答题后才建立。
- 自动计划在最后一次尝试后仍失败时，后续日期不会继续新建空壳或反复付费重试；管理员摘要会显示跳过原因，用户可按现有手动流程处理该失败计划。
- 禁用后，尚未开始的队列项会取消；已经开始的模型调用无法安全中断，可能完成。禁用状态由 Worker 在开始处理前复核。
- 每用户/日期运行标记保留 90 天；计划与运行记录不替换用户已有的作答或复习历史。

## 运维边界

调度器是独立 Worker 容器内已有 headless Worker 子进程的一部分，需要其 Redis 与 PostgreSQL 连接可用。管理员仅保存开关和执行时间；代码部署后不会自动启用，也不会自动修改任何生产设置。启用后会对全部符合条件用户调用其已选模型，可能产生供应商费用。自动化测试使用隔离 PostgreSQL/Redis 和模型 mock，不证明真实供应商响应质量或费用。

管理员页面显示当天生成、跳过、处理中、待处理、失败数量和聚合原因，不展示个人账户列表。重复扫描不会增加已完成或跳过计数。
