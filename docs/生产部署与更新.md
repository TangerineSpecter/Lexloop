# Lexloop 生产部署与更新

本文适用于单台 Linux x86_64 服务器，建议至少 2 核 CPU、4 GB 内存和 40 GB SSD。当前方案面向局域网 IP 访问，使用 Docker Compose 在服务器本地按 Git tag 构建应用镜像，不依赖 GHCR。

## 发布前准备

生产部署只接受以下版本：

- 名称符合 `v主版本.次版本.修订号` 的稳定版本，例如 `v1.0.0`；
- annotated tag，不接受 lightweight tag；
- tag 对应提交必须位于 `origin/master`；
- 根目录及所有 workspace 的 `package.json` 版本必须和 tag 一致。

首次发布前在开发机完成：

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm release 1.0.0
```

`pnpm release` 会提交当前工作区的全部改动、推送当前分支并创建或移动远端 tag。执行前务必检查 `git status`，确认没有密钥、本地数据或无关文件。

## 首次安装

服务器需预装并启动 Docker Engine、Docker Compose plugin、Git、OpenSSL 和 curl。不要在生产机安装 GitHub self-hosted runner。

先在服务器取得对应版本的安装脚本并检查内容：

```bash
git clone --depth 1 https://github.com/TangerineSpecter/Lexloop.git /tmp/lexloop-installer
cd /tmp/lexloop-installer
sudo ./deploy/install.sh
```

不传版本号时，脚本会自动选择 `master` 上最新、可验证的稳定 annotated tag。若必须固定首次部署版本，可传入版本参数，例如 `sudo ./deploy/install.sh v1.2.0`。

脚本是幂等的，会执行以下操作：

1. 在 `/opt/lexloop` 初始化裸 Git 仓库、版本 worktree、配置、状态和备份目录。
2. 生成 PostgreSQL、MinIO、JWT 和 AI 配置加密密钥，保存到权限为 `600` 的 `/opt/lexloop/config/production.env`。
3. 利用 BuildKit/pnpm 缓存构建 Web、API、Worker 和迁移镜像。
4. 启动 PostgreSQL、Redis，执行 `prisma migrate deploy`，再启动应用、Caddy 和独立 updater。
5. 验证 API 返回的版本和 commit SHA，安装每天 03:17 执行的数据库备份计划。

默认入口为：

```text
http://服务器局域网IP/
```

数据库、Redis 和可选 MinIO 不映射宿主机端口。首次启动使用全新数据库，请立即注册第一个账号；现有注册事务保证第一个账号成为唯一 `ADMIN`。在首账号注册完成前，不要把该入口反向代理到公网。

## 配置与 HTTPS

生产配置位于 `/opt/lexloop/config/production.env`。局域网 HTTP 模式保留：

```dotenv
WEB_ORIGIN=http://localhost
COOKIE_SECURE=false
HTTP_PORT=80
```

首次下载 Docker Hub 基础镜像较慢时，可在执行安装脚本前配置 Docker daemon 的 registry mirror；也可以先让脚本生成 `production.env`，把其中 `NODE_IMAGE`、`DOCKER_CLI_IMAGE`、`POSTGRES_IMAGE`、`REDIS_IMAGE`、`CADDY_IMAGE` 改成可信镜像站的完整地址后重新执行。后续构建会复用本机基础层和 pnpm BuildKit 缓存。

如果以后通过宝塔、Caddy 或其他代理使用 `https://lexloop.example.com`，需要把 `WEB_ORIGIN` 改为真实 HTTPS 地址，并将 `COOKIE_SECURE` 改为 `true`。外层代理转发到服务器的 HTTP 80 端口即可；不要代理 PostgreSQL、Redis、MinIO 控制台或 updater。

如由本项目 Caddy 直接终止 HTTPS，可参考 `deploy/Caddyfile.https.example`，配置域名、管理员邮箱和 443 端口后重新创建 gateway。

## 后台检查与更新

唯一管理员进入“设置 → 系统设置 → 系统更新”即可检查和安装版本。updater 每 6 小时也会检查一次，但不会自动安装。

版本判断同时比较 SemVer 和 commit SHA：

- 新版本号指向当前提交的后继提交时，可以更新；
- 同名 tag 被移动到新的后继提交时，显示“同版本修订”；
- tag 指向旧提交、分叉提交、预发布版本或版本号不一致时拒绝更新。

点击“立即更新”后需要重新输入当前管理员密码。流程为：重新校验 tag → 独立 worktree → Compose 配置检查 → 缓存构建 → PostgreSQL 备份 → Prisma migration → 切换容器 → Web/API/版本健康检查。

应用切换失败时 updater 会恢复上一版 Web/API/Worker 镜像。数据库不会自动恢复，因此 migration 必须遵循 expand/contract：先新增兼容字段或表，待所有运行版本不再依赖旧结构后，才在后续版本删除旧结构。

常用诊断命令：

```bash
docker logs --tail 200 lexloop-updater
docker logs --tail 200 lexloop-gateway
docker compose --project-name lexloop --env-file /opt/lexloop/config/production.env \
  --file "$(grep '^CURRENT_RELEASE_PATH=' /opt/lexloop/config/production.env | cut -d= -f2)/deploy/compose.prod.yml" ps
```

updater 的任务状态保存在 `/opt/lexloop/data/updater/update-state.json`。日志会限制长度并隐藏密码、令牌和密钥，updater 只监听 Unix Socket，不开放 TCP 端口。

## 备份与恢复

系统每次更新前创建备份，每天另存一个日备份：

```text
/opt/lexloop/backups/daily
/opt/lexloop/backups/weekly
```

默认保留 7 个日周期和 4 个周周期。建议在 `/opt/lexloop/config/backup-sync` 放置一个仅 root 可执行的同步脚本，将新备份复制到另一台机器或 NAS；备份脚本会把新备份路径作为第一个参数传入。

手动创建备份：

```bash
sudo /opt/lexloop/backup.sh
```

灾难恢复前先保留当前数据库并停止写入服务，再恢复指定备份：

```bash
source /opt/lexloop/config/production.env
release_compose="$CURRENT_RELEASE_PATH/deploy/compose.prod.yml"
docker compose --project-name lexloop --env-file /opt/lexloop/config/production.env \
  --file "$release_compose" stop web api worker
docker exec lexloop-postgres dropdb --force -U "$POSTGRES_USER" "$POSTGRES_DB"
docker exec lexloop-postgres createdb -U "$POSTGRES_USER" "$POSTGRES_DB"
docker exec -i lexloop-postgres pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  --clean --if-exists < /opt/lexloop/backups/daily/要恢复的备份.dump
docker compose --project-name lexloop --env-file /opt/lexloop/config/production.env \
  --file "$release_compose" up -d web api worker gateway
```

恢复必须先在非生产环境演练。数据库备份不包含未来 MinIO 对象；启用文件上传后，需要另外备份 `minio_data` 或使用外部 S3/NAS 的版本管理。
